# Why: the HPA takes the MAX of the per-metric recommendations.
#   cpu:    ceil(4 * 16/70) = 1  -> clamped to minReplicas 2
#   memory: ceil(4 * 68/85) = ceil(3.2) = 4
# A Python process does not give memory back when traffic drops (~87Mi idle on a 128Mi request), so the
# memory metric pins the deployment at its scale-out size. Memory is a poor scale-DOWN signal for this app;
# CPU (or request rate) is the right one. See README 'Lessons learned'.
